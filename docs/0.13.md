# 0.13 本机运行与服务中心

开发包：**0.13.0-dev / Android versionCode 37**，基于 0.12 整理后的已有功能。入口为「设置 → 本机运行与服务」。本版没有接入收费、订阅或广告，也没有发布正式 Release。

## 当前接入的功能

- 检查标准 Termux、arm64、执行权限与可用空间，提供下载、授权、初始化说明和后台设置入口。
- 从 Hermes 官方签名 APT 源安装或升级 stable／canary，先核对公钥指纹，不关闭签名检查。提供模型与接口配置、启停、重启、日志和保留数据卸载。
- 在独立目录 `~/.hermes-mobile` 保存 App 管理的配置、会话与服务，避免覆盖已有 `~/.hermes`。模型通过表单配置；当前已有非 JSON 格式的 YAML 不自动改写，配置失败会保留原文件。
- 自动生成本机连接凭据，Termux 内文件仅所属用户可读写，手机连接凭据通过现有加密存储保存。接口固定绑定 `127.0.0.1:8642`。接口检查通过后才切换到「这台手机」。
- 后续选中 App 管理的本机连接时按需启动已有 Hermes；远程连接不自动启动它。重复操作串行执行，不要求默认打开终端或 tmux。
- 导入单个 `.py` 服务、可选依赖列表，使用独立虚拟环境；管理启停、日志、更新与移除。代码上限 64 KB，依赖填写包名或 `包名==版本`，不接受安装选项和依赖网址。
- 添加 Caddy 本机反向代理，显式填写端口与 HTTP(S) 目标；代理仅监听回环地址。本版没有公网入口配置。
- 安装 Chromium 与 X11 配套包，在独立 Termux:X11 应用查看浏览器。保留专用浏览器资料目录，提供启动与停止；尚未接入 Hermes 自动操作浏览器。
- 通知助手按每个连接保存独立开关、应用白名单、过滤、目标会话、队列与摘要。新连接默认关闭；切换会取消手机端旧发送等待，拒绝旧采集回调，加载新档案。切回来恢复自己的档案。删除连接会清除该档案。

## 首次使用

1. 安装并打开一次标准 Termux（GitHub／F-Droid 版本，0.118 或更新），完成它自己的初始化。需要 arm64 手机，安装前至少预留 2 GB 空间，浏览器和服务可能需要更多。
2. 在本页授予执行权限；点「复制首次初始化命令」，到 Termux 粘贴并运行一次，允许外部应用。原版 Termux 仍需要这一步，不能承诺全程只点按钮。
3. 返回 Hermes，点「检查环境」。若只部署自己的 Python 程序，先准备 Python 服务环境，再导入程序。
4. 部署 Hermes 时填写模型名称、模型 API Key 和接口地址，选择发布通道并阅读实验提示。模型默认使用云端接口，本机运行不代表数据永远不离开手机。
5. 需要浏览器时另装独立 Termux:X11，再安装浏览器配套包、打开浏览器。Android 会要求确认外部 APK 安装，App 不会绕过系统确认。

正常使用以 Hermes 为入口，Termux 在后台执行命令。服务只管理 App 自己创建且启动标识匹配的进程，不按名称批量结束用户其它服务。移除程序保留运行生成的数据；卸载 Hermes 软件包会影响同一个 Termux 中使用该软件包的其它入口，操作前会提示。

## 必须保留的限制

截至 2026-10-24，[Hermes 官方 Termux 文档](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/getting-started/termux.md) 仍明确说明安装包当前不可用、正在修复。因此部署入口标为实验功能，要求用户明确确认；不能把本版描述为已经在手机上安装成功。软件源不可用、指纹不符、命令失败或接口检查失败都不会显示为连接成功。

本环境没有 Android 设备，尚未验证 Termux 的真实权限／命令回包、Hermes arm64 安装、X11 显示输入、Chromium 网页与登录恢复、vivo 后台及通知授权。系统可能回收进程；电池设置和 Termux 手动唤醒锁也不能保证永久保活。本版不擅自申请持续唤醒锁。

自带原生依赖的 Python 程序必须兼容 Android／arm64。虚拟环境不是安全沙箱：服务和导入的依赖在 Termux 的同一用户下执行，可能访问其中其它数据，只应导入可信来源。App 不为任意用户程序自动限制监听地址。

本机 API Key 和当前配置的模型 Key 会在日志展示前清除，并继续套用现有凭据脱敏规则；不能保证未知程序输出的任意私密内容都被识别。不要在程序日志中主动打印秘密。

通知系统授权仍是 Android 全局权限，每个连接的应用内开关另外保存。已经提交给服务器的通知任务无法仅靠切换连接撤回；切回来时沿用原批次与幂等键重试，避免重复新建任务。本版沿用已有通知能力，没有新增独立读取短信数据库的实现。

## 将来合并的入口

`LocalRuntimeBackend` 与 Android 的 `TermuxTransport` 分离，页面依赖统一运行管理器。以后可实现内置后端，替换安装、执行与外部窗口部分，保留连接和服务业务；迁移实际目录、资料、凭据、Android 执行机制和第三方许可仍需单独实现。详见 [接口约定](runtime-backend-contract.md)。

验证记录随开发包提供。桌面 Compose 假后端仅证明界面与业务流程；Python 进程测试使用 Linux 临时目录和假 Hermes／Caddy／浏览器，不证明这些软件已在 Android 真机工作。缺少配置的 RealHermesIT／OpenSshIT 不计入实际通过数。
