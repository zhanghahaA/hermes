# 开发计划

已经做完的见 README 的「开发阶段」。下面是后续计划，顺序和细节会按实际情况调整。用户已决定提前开发 0.15 的通知助手，见 [实现与验证范围](notification-assistant.md)；当前在此基础上开发 **0.16.0-dev** 的持续流式回复、可选工作过程和可拖动 Dock，见 [0.16 说明](0.16.md)。其它项目和长期记忆尚未开始。

总的方向：从“连电脑上的 Hermes”扩展到“**手机本身也能跑 Hermes**”，并且让 Hermes 能用上手机的能力（操作手机、浏览器、通知、智能家居），越用越懂你。

几条原则（和现有功能一致）：

- **每个扩展能力都是可选的，默认关闭。** 打开前在 App 里说明它能做什么、会改什么、有什么风险，用户点了才装、才开；随时能关、能卸载。
- **数据留在本地。** 通知、记忆、家里设备的状态只存在手机 / 你自己的 Hermes 里，App 不往外发。
- **危险操作要你批准。** 例如操作手机、开门锁、发消息，走 Hermes 的审批卡片。
- **没在真机上验证过的不说能用。** 每一项都写明哪些能自动测试、哪些只能真机确认。

## 0.12：集成 Termux，一键安装本地 Hermes

让不想开电脑的人，直接在手机上跑 Hermes。

- **检查环境**：是否装了 Termux（要 F-Droid / GitHub 版，Google Play 上的旧版不行）、手机是不是 arm64、存储空间够不够。缺什么就引导去装。
- **一键安装**：用 Hermes 官方的 Termux 安装方式（签名的 APT 源，`stable` / `canary` 两个通道，安装前核对仓库公钥指纹），
  不用桌面版的 `install.sh`。App 经 Termux 的 `RUN_COMMAND` 接口执行安装命令，界面上显示每一步的进度和输出。
  - Termux 默认不让别的 App 发命令：需要用户在 `~/.termux/termux.properties` 里打开 `allow-external-apps`。App 给出一键复制的命令和图文说明。
- **自动配置**：生成 `API_SERVER_KEY`、写好 `.env`、选模型和填模型的 Key（写在手机上的 Hermes 里，不经过别处）、启动 gateway，
  然后自动建一个「这台手机」的连接。
- **保活**：`termux-wake-lock`、引导关掉电池优化、说明 vivo 等系统的后台限制和 Android 12+ 的“子进程限制”（phantom process killer），能检测到被杀就提示怎么处理。
- **管理**：一键启动 / 停止 / 重启 gateway、看日志、升级、卸载。
- **风险**：Hermes 官方文档（2026-09 的源码）写着 Termux 包“目前坏了，正在修”，要等官方修好；只支持 arm64；手机上跑会比较耗电。
- **验证**：安装脚本的拼装和解析能自动测试；真正的安装、保活只能在真机（包括用户的 vivo）上确认。

## 0.13：扩展能力框架 + 智能家居 + 操作手机

### 扩展能力框架

一个「扩展」页面，统一管理下面这些可选能力：介绍、风险说明、安装 / 开关 / 卸载、状态（在不在跑、最近做了什么）。
扩展装在哪台 Hermes 上就在哪台生效（手机本机的或电脑上的）。

### 智能家居（Home Assistant）

- 用 Hermes 官方的 `homeassistant` 插件（`hermes plugins install homeassistant`）：能查询、控制设备，也能订阅设备状态变化。
- App 里填 Home Assistant 地址和长期访问令牌（`HASS_URL` / `HASS_TOKEN`，写进 Hermes 的 `.env`），测试连接，选给哪些 bot 装。
- 聊天里直接说“把客厅灯关了”；状态变化（门开了、温度过高）可以当提醒推到手机。
- 门锁、燃气这类设备的操作必须经过审批。
- 小米 / 涂鸦等设备：通过 Home Assistant 的对应集成接入，不单独对接。
- **验证**：可以起一个本地的 Home Assistant 测试实例自动测试；用户家里的设备只能真机确认。

### 操作手机（ADB 无线调试）

- 原理：Android 11+ 的「无线调试」。在 Termux 里装 `android-tools`，App 引导完成配对（`adb pair`），之后 Hermes 经 `adb` 截屏、读界面结构、点击、输入、打开 App。
- 以 Hermes 技能 / MCP 工具的形式提供，Hermes 跑在手机上时直接连本机；跑在电脑上时也可以连同一局域网里的手机。
- 安全：这等于把手机的控制权交给 Hermes。默认每个操作都要批准，可以设白名单（比如只允许操作某几个 App）；随时一键断开；App 顶部常驻提示“Hermes 正在操作手机”。
- 限制：无线调试在重启、换 Wi-Fi 后会关掉，要重新打开（vivo 上的具体表现要真机确认）；有的 App 禁止截屏。
- **验证**：命令拼装、工具接口能自动测试；配对和实际操作只能真机确认。

## 0.14：手机上的本地浏览器（Chromium + X11）

- 在 Termux 里跑完整的 Chromium（Termux:X11 或 VNC 显示），Hermes 用它的本地浏览器方式（CDP，`/browser connect`）操作网页：登录后的网站、填表、查资料。
- 画面可以直接在 App 里看、随时接管（复用现在的「Bot 屏幕」：查看器、接管 / 交还）。
- 限制：很吃内存和电，低配手机可能跑不动；Hermes 的 `computer_use`（整机桌面操作）官方没有 Android 版，这里只做浏览器。
- **验证**：浏览器连接和画面传输可以在 Linux 上模拟测试；手机上的性能只能真机确认。

## 0.15：读取手机通知（危险，默认关闭）+ 越用越懂你

### 读取手机通知

- App 用 Android 的通知读取权限（NotificationListenerService），**只转发你选定的 App 的通知**给 Hermes，比如快递、日程、工作群。
- Hermes 可以据此提醒、汇总（“今天有 3 个快递到了”）、或者在你问的时候参考。
- 风险很高，所以：
  - 默认关；打开时单独确认一次，说清楚能看到什么。
  - App 白名单 + 关键词过滤；验证码、银行、支付类通知默认屏蔽、内容打码。
  - 只存在本地的 Hermes 里，可以随时查看、删除已转发的内容。
- **验证**：过滤和打码规则能自动测试；通知权限和各品牌系统的行为只能真机确认。

### 越用越懂你

- 基于 Hermes 自己的记忆（`MEMORY.md` / `USER.md`、记忆插件）和技能：
  - 聊天里一键“记住这个”；定期让 Hermes 整理记忆，App 里可以审阅、修改、删除（现在的「记忆」管理页继续扩展）。
  - 用户同意的前提下，把通知、日程、常用操作里的规律总结成偏好（比如“早上 8 点前不打扰”“常点的外卖”）。
- 所有记忆都是你自己 Hermes 里的文件，看得见、改得了、删得掉。
