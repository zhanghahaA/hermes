## 0.14.6 以来的新变化

**修好：在手机上一键部署 Hermes 总是失败。** 在真机上一步步复现，依次卡在三个地方：

- **「验证连接」一直提示「本机聊天接口尚未就绪」（根本原因）。** Termux 版 Hermes 自带的 Python 环境里没有聊天接口要用的 `aiohttp`，Hermes 启动后聊天接口（8642）永远起不来，日志里只有一行 `API Server: aiohttp not installed`。现在安装、升级 Hermes 之后，以及每次启动之前，App 会检查一次；缺的话用 Hermes 包里自带的 `uv`、按 Hermes 自己指定的版本，从清华镜像补装进去。已经装好时只做一次本地检查，不联网。补装失败会单独说明原因，点「重启并重试」会再补一次。
- **点「安装 Hermes」马上失败（代码 44）。** Hermes 官方的稳定版通道目前没有安装文件，只有预览版能下载。现在遇到这种情况，主按钮直接是「改用预览版安装」，「再试一次稳定版」降为小按钮。仍然不会自动换通道，要你点了才换。
- **模型名称里填了网址也能保存。** 「OpenAI API」这类固定提供方没有地址栏，网址容易被填进模型名称。现在模型名称是网址时会标红、不能保存，并提示改用「自定义端点」，在「模型接口地址」里填写。

**聊天出错时，原因会留在聊天里。** 以前模型调用失败，原因只在几秒就消失的弹出提示里，聊天里只剩一句英文「Your request was not processed」，不知道该改什么。现在出错的那一轮下面会一直留一行红字说明原因，比如「这条没有完成：……这个 Key 只允许 hy4-preview」。不打开「显示工作过程」也能看到。

## 验证

- 桌面测试全量 331 项，0 失败；Python 脚本测试 51 项，47 项通过、4 项要真 Hermes 源码的跳过，0 失败。新增测试覆盖：补装 aiohttp 的脚本（缺少时补装、已有时不联网、不是打包安装时跳过、补装失败）、启动前先检查、改用预览版的按钮、网址当模型名被拒、失败原因留在聊天里。
- **在真机（vivo，Android 14）上验证过**：把手机上 Hermes 相关的 App、软件包和数据全部删掉，再装 CI 打的测试包，按新手的方式从头操作：授权 → 在 Termux 粘贴初始化命令 → 安装（稳定版缺文件，点「改用预览版安装」）→ 83 秒装完，aiohttp 自动补上 → 配置自定义端点 → 「保存并开始聊天」90 秒后进入聊天 → 模型正常回复。换成 Key 不允许的模型时，聊天里留下了红字原因。真机上装的是 CI 测试包，不是这个正式签名的包。

## New since 0.14.6

**Fixed: one-tap deployment of Hermes on the phone kept failing.** Reproduced step by step on a real phone; it stopped at three places in turn:

- **"Verify connection" always said the local chat API was not ready (root cause).** The Python environment bundled with the Termux Hermes package lacks `aiohttp`, so Hermes' chat API (port 8642) never starts; the only trace is one log line, `API Server: aiohttp not installed`. After installing or upgrading Hermes, and before every start, the app now checks for it and, if missing, installs the version Hermes itself pins into that environment with the `uv` bundled in the package, from the Tsinghua PyPI mirror. When it is already there this is a single local check with no network access. A failed install is reported with its own explanation, and "Restart and retry" tries again.
- **"Install Hermes" failed immediately (code 44).** Hermes' official stable channel currently has no package files; only the preview channel can be downloaded. In that case the main button is now "Install from the preview channel" and "Try stable again" becomes a secondary button. The app still never switches channels on its own; it only does so when you tap.
- **A URL could be saved as the model name.** Fixed providers such as "OpenAI API" have no address field, so the URL easily ended up in the model name. A model name that is a URL is now highlighted, cannot be saved, and the hint points to "Custom endpoint", where the address belongs in "Model API address".

**When a chat turn fails, the reason stays in the chat.** The reason used to appear only in a pop-up that disappeared after a few seconds, leaving just Hermes' generic "Your request was not processed" in the chat. The failed turn now keeps a red line with the reason underneath, for example that the API key only allows `hy4-preview`, even when "Show work process" is off.

## Install

Same signing key as 0.14.6: install over it directly. If you are still on 0.14.1 or earlier, read the 0.14.5 notes first (that release changed the signing key and requires uninstalling).

331 desktop tests, 0 failures; 51 Python script tests: 47 pass, 4 that need real Hermes sources skipped, 0 failures. New tests cover the aiohttp script (installs when missing, no network when present, skips non-packaged installs, install failure), the check before start, the preview-channel button, rejecting a URL as model name, and keeping the failure reason in the chat.

**Validated on a real phone (vivo, Android 14):** after removing every Hermes app, package and data, a CI test build was installed and set up from scratch as a beginner would: permission, paste the init command in Termux, install (stable missing, so "install from preview"), installed in 83 s with aiohttp added automatically, custom endpoint, "Save and start chat" reached the chat in 90 s, and the model replied.
