## ⚠️ 这一版换了签名，要先卸载旧版

之前的签名丢了，0.14.2 起用新的签名。Android 不允许不同签名的包互相覆盖，所以**必须先卸载手机上的旧版 Hermes，再安装这个包**。

卸载会清掉 App 自己存的东西：连接设置、App 里的 SSH 密钥、设置、草稿、通知助手的记录。**电脑上 Hermes 里的对话、bot、定时任务都不受影响**，重新连上就都在。

卸载前建议记下：每个连接的地址、端口、用户名、「文件上传位置」等设置。装好后按「添加连接」重新配置；SSH 连接要复制新的配置命令，到电脑上再跑一次，给手机的新密钥授权。

以后的版本都用这把新签名，可以直接覆盖安装。

## 0.14.1 以来的新变化

**修好：电脑上能接着聊的长对话，手机上发消息报 `session_read_only`。** 对话聊得久了 Hermes 会压缩上下文，会话列表里给的是压缩后最后一段的号；电脑版打开时会换成这个对话真正的号再聊，手机 App 以前还拿列表里那段的号去发，被 Hermes 当成了只读存档。现在发消息、改名置顶、停止、回答审批都用换过的号，这类对话（包括 bot 的对话）在手机上可以接着聊。

**能看但不能接着聊的旧对话，现在会说清楚原因。** 新版 Hermes（2026-10-23 起）把一部分没有归属的旧对话设成只读，比如以前经 API 建的、网页版或导入的对话。往里发消息时，App 以前只弹一句「发送失败：Hermes gateway：session_read_only」，现在会：

- 说明这是 Hermes 存档的旧对话，只能查看；
- 把这个对话标成只读，底部显示「新建对话」，点了会开一个新对话，**刚才没发出去的那条会自动放进输入框**；
- 让「分叉」菜单变灰，因为 Hermes 对这种对话也拒绝分叉。

电脑上建的对话、手机经 SSH 新建的对话不受影响，电脑和手机两边都能接着聊。

## ⚠️ New signing key: uninstall the old app first

The previous signing key was lost, so 0.14.2 is signed with a new key. Android does not allow installing over an app signed with a different key: **uninstall the old Hermes app first, then install this APK.**

Uninstalling clears data stored in the app itself: connections, the app's SSH key, settings, drafts and notification-assistant records. **Conversations, bots and scheduled jobs on your computer's Hermes are not affected.** After reinstalling, add your connections again. For SSH connections, run the new setup command on the computer again to authorize the phone's new key.

Future releases keep this key and install over 0.14.2 normally.

## New since 0.14.1

**Fixed: long conversations that continue fine on the computer failed on the phone with `session_read_only`.** After Hermes compresses a conversation, the session list shows the id of its latest segment; `session.resume` maps it to the conversation's real id, which the desktop then uses. The app kept sending to the listed segment id, which Hermes treats as read-only stored history. Sends, rename/pin, stop and approval answers now use the resumed id, so these conversations (including bot chats) can be continued from the phone.

Stored conversations that newer Hermes opens read-only (refusing sends with `session_read_only`, e.g. old API-created, WebUI or imported chats) are now explained instead of showing the raw code. Such a chat is marked read-only, and a **New chat** action opens a fresh conversation with the unsent message prefilled. Fork is disabled for these chats because Hermes refuses it as well. Conversations created on the computer or from the phone over SSH are unaffected and can be continued on both.
