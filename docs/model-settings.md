# 模型设置与本机部署（0.13.4-dev）

## 在手机里配置模型

设置 → **模型与提供方**，针对当前连接和当前 Bot 的 Hermes 配置目录操作。远程连接需已连通 SSH；仅有 HTTP 聊天接口的连接需要先补充 SSH。App 管理的「这台手机」通过 Termux 命令桥操作，不要求额外配置 SSH。

1. 选择提供方。列表来自目标 Hermes 的实际能力，常见服务排在前面。
2. API 密钥服务：粘贴服务商密钥；已有凭据可以留空保留。
3. 订阅账号：Hermes 支持设备码授权的，点「连接订阅账号」→「开始授权」，再「复制授权码并去授权」，在浏览器完成授权。返回 App 会检查结果。账号 token 由目标 Hermes 保存，手机只拿授权码和状态。
4. Hermes 仍要求命令行的账号，复制页面生成的登录命令，在对应服务器／Termux 执行一次，再刷新。命令带上实际 HERMES_HOME，避免登录到另一份配置。Anthropic 等沿用上游的原有登录方式，没有擅自增加绕过上游限制的网页授权。
5. 填写模型名称，或读取模型清单后选择。模型清单不可用时可手动填写，不冒充已经验证模型能回复。
6. 点「保存模型配置」并确认。模型默认写回服务器；清除手机上该连接的旧新会话默认覆盖并刷新清单。已明确锁定模型的旧会话仍需单独切换。

本机的保存按钮为 **保存并开始聊天**：配置成功后启动 Hermes，检查本机接口，通过后切换「这台手机」并进入新聊天。接口检查失败会保留错误说明，可重新启动连接；不会把未通过检查显示为成功。

### 自定义端点

支持 OpenAI Chat Completions、Responses、Anthropic Messages 格式，按服务商提供的实际地址和模型名称填写。每个 Hermes 配置目录保留一份 App 管理的自定义端点和一份本地端点，使用 Hermes 的命名端点与密钥引用接口，密钥写到 Hermes 的凭据位置，不直接写进 config.yaml。保留其它自定义端点和无关配置。

### 本地模型

提供 Ollama、LM Studio、llama.cpp 地址快捷选择，也可以填写兼容接口地址。这里连接**已经运行的模型服务**，不安装 Ollama、不下载 GGUF。localhost 指 Hermes 所在机器：远程 Hermes 指远程电脑，本机 Hermes 指手机。可以填写本地服务访问密钥（可选）。

云端端点要求 HTTPS，Hermes 所在机器的回环地址允许 HTTP；本轮不开放带密钥的明文局域网 HTTP 端点。

## Termux：首次配置与安装

0.13.4-dev 将主流程收敛为一个随状态变化的按钮。「检查详情」与「高级功能」默认收起，Python 服务、反向代理、X11 浏览器、升级和卸载不再挤在安装流程中。

1. 在欢迎页选「直接在这台手机运行」，或「设置 → 在手机上安装 Hermes」。未安装 Termux 时，主按钮直接打开下载；安装后打开一次，再返回。
2. 页面提示授权时点「授予权限」。系统没有弹窗可点旁边的系统权限入口。返回自动检查。
3. 仅当 Termux 明确拒绝外部调用时，显示「复制命令并打开 Termux」。粘贴并回车后返回，权限没有变化也会自动重查。已完成初始化的设备不再重复展示命令。
4. 点「安装 Hermes」即明确同意执行按钮旁说明的安装与配置：检查命令连通、准备缺失依赖、安装缺失的 Hermes、配置手机接口连续完成，无需再点准备或确认。默认稳定版，预览版选择保留在高级功能。已有软件不重新下载安装；失败停止，重试重新检查并复用完成的步骤。
5. 成功后自动进入模型设置，选择服务商与模型，填写账号或密钥，点「保存并开始聊天」。本机保存不再重复弹窗，成功后自动启动、检查连接并进入聊天；远程配置保留确认。

环境已就绪时，App 内安装只需一次点击；后续模型设置完成后一次点击保存并聊天。首次安装外部应用、系统授权、终端粘贴和服务商登录仍需用户完成，不承诺所有初始状态都能两次点击完成。

Termux 回包修复：v0.118.3 的插件错误码 err=-1 表示成功（Android RESULT_OK），与 shell exitCode=0 不同。旧版按 err!=0 判错，会把正常命令当作失败。现在共享解析器按真实协议区分成功、拒绝、结果缺失和 shell 失败；不完整结果不标记成功。错误分类和数字代码进入「复制检查结果」，原始命令、账号、密钥和日志不导出。只读检查不会安装软件。

安装使用原生 Termux 官方签名 APT 通道，默认 stable，可选 canary；本轮没有加入 Linux 兼容层。签名、网络或软件包运行失败会停止并显示失败阶段，不绕过签名、不报假成功。这里的代码验证不能替代手机 arm64 实装验证。

首次系统授权和终端粘贴仍需用户完成；模型 API 密钥必须由服务商或用户提供，不能自动生成。系统没有可交互授权入口时，可能需要先安装 Termux 再覆盖安装 Hermes App，使系统重新识别自定义权限；不要为排错清除数据或卸载 App。

## 隔离与隐私

- 本机目录与每个远程连接／Bot 的 HERMES_HOME 分开操作，不在不同连接之间自动复制密钥。两个连接如果指向同一个 Hermes 配置目录，本质上共享配置；Qwen／Claude 等外部 CLI 的账号也可能由该机器的全局登录管理。
- 保存配置、发起账号登录都先在 App 中说明作用目标，点击确认后才执行。首次模型修改前备份 config.yaml 与 .env；后续不覆盖这份初始备份。
- API 密钥走 SSH 标准输入或 Termux 的受控命令输入，不放到命令行参数、临时脚本、普通界面状态或诊断中。未提交输入不写入 Android 保存状态。手机连接凭据继续使用 Keystore。
- 账号授权码的复制标记为敏感。临时授权状态写入该 Hermes 的私有目录，文件 600、目录 700，回包不包含 token；发起／轮询／取消不占用持续的 SSH 会话。取消与服务商已完成授权之间存在时序边界，刷新可查看最终账号状态。
- 云端模型仍会接收发给它的聊天内容；“Hermes 运行在手机上”不等于模型在手机上运行。

## 通知助手首次进入

取消进入页面时的同步应用扫描。只有打开应用选择器才在 IO 线程查询应用、读取名称；列表懒加载，查询期间可以关闭选择器。结果短时缓存。保持既有按连接独立的通知授权、白名单和加密记录。

桌面测试用受控的未完成后台查询验证页面仍能响应；未在用户 vivo 手机上采集冷启动耗时，不能把代码修复描述成已测得消除某个毫秒数。

## 验证方式

标准桌面测试与 Android 构建之外：

```bash
python3 -m unittest discover -s tools/runtime-tests -p 'test_*.py'
```

可选真实 Hermes 源码集成（临时目录、假密钥、不调用付费模型；没有环境时明确跳过）：

```bash
HERMES_PROVIDER_TEST_SOURCE=/path/to/hermes-agent \
HERMES_PROVIDER_TEST_PYTHON=/path/to/its/python \
python3 -m unittest discover -s tools/runtime-tests -p 'test_*.py'
```

账号协议的自动回归替换了服务商授权流程；真实账号浏览器授权仍需本人在设备确认。真实 Android 执行权限、跨 App 返回、arm64 安装和首条模型回复均需真机验证。
