# 0.13.1：少填信息，按按钮完成连接

> 本文保留 0.13.1 的连接引导记录。本机安装当前流程见 [0.13.4 部署与模型设置](model-settings.md#termux首次配置与安装)。

开发包为 **0.13.1-dev / code 38**，基于 main 的 0.13。基础聊天、通知档案和本机运行能力保留。本轮调整欢迎页、连接向导、Termux 初始化、通知助手和 Bot 屏幕安装提示。

## 电脑／服务器：两个主要按钮

前提：机器上已经安装 Hermes、能以自己的 SSH 账号登录，并且手机能访问它的 SSH 地址。可用终端为 Linux、macOS 或 Termux；本轮未提供 Windows PowerShell 命令。

1. 欢迎页选「连接电脑或服务器」，填写地址和 SSH 用户名。端口、连接名称等有默认值，需要时才展开高级设置。电脑在另一张网络时，仍需用户自己已配置可达的 VPN 或 SSH 入口。
2. 点「生成并复制配置命令」，以刚才填写的 SSH 用户登录那台机器，在终端粘贴并按回车。手机自动生成 Ed25519 密钥，不需要手动创建密钥文件；已有导入密钥或密码登录仍可在高级设置中使用。
3. 执行完成后回到手机，点「检查并连接」。App 经认证的 SSH 自动获取实际 API Key 和端口，检查通过后保存、切换连接并退出向导；不用再点一次保存。

“两个按钮”指地址与账号填好之后的手机主流程。首次在服务器粘贴执行一次、输入服务器账号、确认 Android 权限与安装外部应用仍需要用户操作，不能承诺任何初始状态都只需两次点击。

### 配置命令会做什么

- 优先使用系统 Python 3；没有时尝试 Hermes 自带的 Python，Termux 缺少时会安装 Python。没有可用运行环境会明确失败。
- 使用当前 `HERMES_HOME`，默认 `~/.hermes`；指定非默认 Profile 时使用其 profiles 子目录。
- 先备份已有 `.env` 到 `.env.before-mobile-setup`，保留其它设置，不覆盖原始备份。
- 开启手机接口，保留已有有效 API Key 和端口。没有密钥时创建随机密钥。SSH 场景的配置命令不包含 API Key，由服务器生成、再通过 SSH 获取；命令始终不包含手机私钥或 SSH 密码。
- SSH 密钥登录时将本手机公钥加入当前登录用户的 `authorized_keys`，设置目录与文件权限，相同公钥重复执行不重复添加。没有替用户安装或开启远程机器的 SSH 服务。
- SSH、HTTPS 与本机连接保留原监听地址，未配置时默认回环地址。直连会验证手机填写的地址确实属于运行命令的机器，再设置为该监听地址；拒绝通配地址。
- 请求重启 Hermes gateway，可能中断正在进行的回复。界面在复制前说明这项影响，只有用户实际执行所复制的命令才会修改服务器。

结果暂存在服务器的 `.mobile-setup-results/<本次配置标识的摘要>`，文件权限 600，供手机经 SSH 读取。里面含连接密钥，可在连接成功后自行删除。它属于配置数据，不是公开诊断文件。读取请求只发送摘要；回包必须包含本手机生成、由用户粘贴到服务器的随机配置标识，验证后才填入密钥及主机指纹。后续接口检查使用该指纹，已有指纹不符仍拒绝连接。

如果使用自定义 `HERMES_HOME`，复制命令的终端和 SSH 登录环境应指向同一目录；不一致时可用下面的手动结果导入，或在高级设置中填写已知参数。

## 已有直连／HTTPS 或自动获取失败

已有地址和 API Key 时，可以直接「粘贴已有 API Key」再检查。需要开启接口时也能复制完整配置命令，不再提供 `<随机长密钥>` 之类示意占位内容。

执行后，终端会输出以 `HERMES-MOBILE-SETUP:` 开头的连接码。复制完整一行，回手机点「粘贴配置结果」即可自动填入实际密钥和端口。只接受与当前页面的配置标识及目标参数相符的结果；不会把其它机器的回包误用到当前连接。

连接码是编码后的私密配置，**编码不等于加密**，不要发到公开群聊。含密钥的复制操作会向 Android 标记为敏感内容；系统剪贴板行为仍由系统版本决定。App 不在页面加载时主动读取剪贴板，只有点击粘贴时读取。未保存的私钥和输入密钥不写入 Android 保存界面的 Bundle；保存后的凭据沿用 Keystore 加密存储。页面若被系统完全重建，未保存的密钥可能丢失，需要重新复制当前配置命令执行。

## 手机本机、通知和屏幕

- 欢迎页选「直接在这台手机运行」直接进入本机运行中心。安装、首次授权和准备环境按步骤显示，不再先要求用户手填本机 API Key。
- 「复制并打开 Termux」把初始化命令放到剪贴板并打开 Termux，提示长按粘贴、按回车、返回授权。系统授权不能代点。
- 高级设置中的手机文件互通也提供 SSH 服务准备、公钥安装和存储授权的复制按钮，默认只监听本机回环地址。
- 环境准备好后，再部署本机 Hermes；安装不要求先填模型 Key；安装后在「模型与提供方」中配置服务，保存后启动并连接。原版 Termux 首次仍需执行一次初始化命令，系统执行权限未通过时提供可点击的检查和系统设置入口。详见 [0.13.2 模型设置与部署](model-settings.md)。
- 通知助手根据当前缺少的步骤，依次引导系统授权、应用选择、固定会话和开启，不继承其它连接的档案。
- Bot 屏幕缺少组件时，安装提示有明确的复制按钮、执行位置和安装后返回刷新的说明。

## 验证边界

自动测试包含实际执行完整复制命令（临时目录、假 Hermes）、真实本机 SSH 认证与配置回包、表单自动生成／粘贴／失败不保存，以及 Python 文件权限、备份、重复执行和现有配置保留。真实 Hermes 服务器、macOS 及 Android 手机上的安装、授权、剪贴板和跨应用恢复仍需实测。没有把假模型／假服务测试当成用户设备已验证。

本轮完整套件报告 228 项，其中 212 项实际通过、0 失败；16 项真实 Hermes／OpenSSH IT 缺少环境而未执行。另 17 项 Python 运行与配置测试通过。App 与 Android 自检 APK 构建成功，相关浅／深色截图已检查；没有 Android 设备，自检 APK 未在设备上执行。

回归中同时修复了原有定时任务操作的回包竞争：同一任务按操作顺序提交，删除确认后不被旧回包恢复，切换连接后的旧操作不更新新列表。工具集也在发布数据前先发布对应可用能力，避免页面短暂读到不一致状态。
